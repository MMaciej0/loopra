# Backend Design — `apps/api`

Fastify-based REST API. The central service that powers both the web app and mobile app.

---

## Module Convention

Every feature module follows the same internal structure:

```
modules/<name>/
  index.ts      # Registers Fastify plugin, mounts routes on a prefix
  routes.ts     # Route definitions (method, url, schema, handler)
  schema.ts     # Zod schemas for request body, params, query, response
  service.ts    # Business logic — pure functions, no Fastify types
```

`service.ts` receives `db` as a parameter, making it independently testable.

## Authentication Flow

- **Access token**: short-lived JWT (15 min), sent as `Authorization: Bearer <token>`
- **Refresh token**: long-lived (30 days), stored in `httpOnly` cookie, also accepted in body
- On refresh: rotate refresh token, issue new access token
- Refresh token stored in Redis; logout invalidates it

## Geospatial Queries

All location-based queries use PostGIS `ST_DWithin` with geography type for accurate distance in meters.

Example — nearby events within 50km:
```sql
WHERE ST_DWithin(
  events.start_location::geography,
  ST_SetSRID(ST_MakePoint($lng, $lat), 4326)::geography,
  50000  -- meters
)
ORDER BY events.start_location <-> ST_SetSRID(ST_MakePoint($lng, $lat), 4326)
```

## Pagination

All list endpoints use **cursor-based pagination** (not offset) for consistent results on frequently-updated datasets.

Request: `?cursor=<opaque_string>&limit=20`
Response: `{ data: [...], nextCursor: "<string>" | null }`
